A device-driver platform you actually own.

Oak is a JSON manifest format, a sandboxed Node.js runtime, and an orchestrator that hosts your own device drivers — lights, thermostats, alarms, media, sensors — behind one dashboard you control end to end. No vendor cloud, no subscription, no black box.

Architecture

Three small, honest layers

No framework to learn beyond JSON and plain Node.js. Each layer has one job and stays out of the others' way.

01

Manifest

A JSON file describes a device integration — its actions, states, roles (on/off/level/arm), and transport (TCP, HTTP, MQTT). No code required to declare what a driver can do.

→
02

Sandboxed runtime

Driver code runs in its own vm.Context, wired to a real TCP Connection or HttpClient depending on the manifest. One misbehaving driver can't take down the host.

→
03

Orchestrator

Hosts every driver instance behind one REST + WebSocket API, and serves the admin panel, live dashboard, 3D scenes, and Layout builder that sit on top of it.

What's built on top

Everything a real dashboard needs

Not just a driver runtime — a full admin + live control surface, built and battle-tested against real hardware.

🎛️

Dashboard bindings

Name a device once ("kitchen light"), pick its On/Off/Level functions from any driver instance, and it shows up everywhere — Live, Layout, 3D — automatically in sync.

🗂️

Custom categories

Light, Switch, Climate, Security, Media, Sensor and Generic ship built in — add your own categories alongside them and reorder the whole list to match how you think about your home.

🏠

3D scenes

Upload a .glb model of a room, bind meshes to devices, and watch doors swing, blinds roll, and lights glow in real time as the underlying device state changes.

🧩

Layout builder

A drag-and-drop, 12-column dashboard editor for building a custom page per room or per user, mixing device tiles, cameras, macros, and links.

🎙️

Voice control

Speak a device's name and Live resolves it to the right zone on the right hub, even when several devices share one physical instance.

🎬

Macros & automations

Chain actions across drivers into one macro, and trigger them on schedules, sunrise/sunset, or conditions — no code, configured entirely from the admin panel.

📷

Camera streaming

RTSP feeds transcoded through ffmpeg to browser-native WebSocket/MSE — no plugin, verified against real IP cameras.

🛡️

Per-driver sandboxing

Every driver instance is isolated in its own JS context with its own error boundary — a crash in one driver never takes the orchestrator down.

Get running

Install in one line, or step by step

The script sets up Node.js (if it's missing), clones the repo, installs dependencies, and registers Oak as a systemd service that starts on boot and restarts on crash.

One line, on a fresh Debian/Ubuntu machine

Downloads and runs the installer directly — no manual clone needed.

curl -fsSL https://raw.githubusercontent.com/qinghuaatbc/oak/main/scripts/install.sh | bash

Or clone first, run locally

Same result — useful if you want to read the script before running it.

git clone https://github.com/qinghuaatbc/oak.git ~/oak-app/oak
~/oak-app/oak/scripts/install.sh          # defaults to port 8702
~/oak-app/oak/scripts/install.sh 8080     # or pick your own port

Open the admin panel

From any device on the same network as the install:

http://<machine-ip>:8702/admin.html   # configure drivers, dashboard, layout
http://<machine-ip>:8702/live.html    # the day-to-day control surface

Re-run any time to update

The script is idempotent — it pulls the latest code, reinstalls dependencies, and restarts the service.

~/oak-app/oak/scripts/install.sh
Optional

Going public with HTTPS

The installer only exposes Oak on your local network, over plain HTTP. To reach it from outside — with a real domain and a certificate — put a reverse proxy in front. Caddy is the easiest option: it requests and renews Let's Encrypt certificates automatically.

# /etc/caddy/Caddyfile
your-domain.com {
    reverse_proxy localhost:8702
}

That's the entire config. Point your domain's DNS A record at the server's public IP, install Caddy, drop the block above into /etc/caddy/Caddyfile, then:

sudo systemctl reload caddy

Caddy handles the certificate on first request — no manual renewal, no separate certbot step. If you want the dashboard password-protected too, add a basic_auth directive — just remember to exclude the /ws path, since browsers don't reliably send cached Basic Auth credentials on WebSocket upgrade requests.

Honest status: Oak is under active development, not a finished product. The core (manifest → sandboxed runtime → orchestrator) is solid and running real hardware in production; some driver command sets are a plausible starting point rather than verified against every device's full protocol. Read SPEC.md for the design rationale, including an explicit note on independence from any third-party driver SDK.
